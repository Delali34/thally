## MDX basics

Every page in Thally is an `.mdx` file — Markdown with JSX support. You can use standard Markdown syntax plus React components inline.

```mdx
# Heading

Regular paragraph with **bold**, *italic*, and `inline code`.

- Bullet lists
- Work as expected

1. Numbered lists too
```

## Frontmatter

Every page needs a frontmatter block at the top:

```yaml
---
title: Page Title
navTitle: Short label
description: A short summary for search results and meta tags.
---
```

| Field | Required | Purpose |
| --- | --- | --- |
| `title` | Yes | Page heading, browser title, and search result |
| `navTitle` | No | Shorter sidebar and previous/next label |
| `description` | Yes | Meta description and search snippet |
| `descriptionPlacement` | No | `body` hides a summary already present in the body. On an `openapi:` page, `operation` keeps the summary for metadata and shows the full operation description instead. |

The title from frontmatter is automatically rendered as the page heading — you don't need to add an `# H1` in the body.

## Code blocks

Fenced code blocks get syntax highlighting automatically:

````mdx
```javascript
const greeting = 'Hello from Thally!'
console.log(greeting)
```
````

Thally highlights common documentation languages including JavaScript,
TypeScript, Bash, Python, JSON, Java, Go, Rust, C/C++, C#, PHP, Ruby, Swift,
GraphQL, SQL, Vue, and Svelte. Other language identifiers remain readable as
escaped plaintext, so an uncommon fence never prevents a page from rendering.

## Callouts and notes

Use `<Note>`, `<Tip>`, `<Info>`, `<Warning>`, `<Check>`, or `<Danger>` to highlight important information. A single sentence takes the callout colour; add a `title` when the callout carries more, and the body stays in ink:

```mdx
<Tip>
  A single sentence reads in the callout colour.
</Tip>

<Warning title="Heads up">
  Titled callouts support **Markdown**, links, and lists in the body.
</Warning>
```

The generic `<Callout icon="key" color="#C77DFF">` form makes a custom callout from one colour. See [Callouts](/components/callouts) for every type and prop.

## Links

Standard Markdown links work for both internal and external pages:

```mdx
Check the [Quickstart](/quickstart) guide or visit [GitHub](https://github.com).
```

## Tabs

Use `<Tabs>` and `<Tab>` to show platform-specific or variant content without code blocks:

```mdx
<Tabs>

<Tab title="macOS">
Install with Homebrew:
\`\`\`bash
brew install your-cli
\`\`\`
</Tab>

<Tab title="Linux">
Install with apt:
\`\`\`bash
sudo apt install your-cli
\`\`\`
</Tab>

</Tabs>
```

Each `<Tab>` supports full MDX content inside — code blocks, lists, callouts, and more.

## Steps

Use `<Steps>` and `<Step>` for sequential instructions with numbered circles and connector lines:

```mdx
<Steps>

<Step title="Install">
Run the installer:
\`\`\`bash
npm install your-package
\`\`\`
</Step>

<Step title="Configure">
Create a config file and add your API key.
</Step>

</Steps>
```

## Cards

Use `<CardGroup>` and `<Card>` to create clickable card grids for landing pages or "next steps" sections:

```mdx
<CardGroup cols="2">

<Card title="Quickstart" href="/quickstart" icon="book-open">
Get up and running in five minutes.
</Card>

<Card title="API Reference" href="/api" icon="code-simple">
Explore the full API.
</Card>

</CardGroup>
```

Available icons: `book-open`, `code-simple`, `grid-round`, `link-simple`, `wrench`, `party-horn`, `telegram`, `envelope`, `x-twitter`, `message`.

## Images and frames

Place images in the `public/` folder and reference them with a leading slash:

```mdx
![Screenshot](/images/image1.jpg)
```

Wrap images in a `<Frame>` for a styled border with an optional caption. Frames are click-to-zoom by default:

```mdx
<Frame caption="System architecture overview">
  ![Screenshot](/images/image1.jpg)
</Frame>
```

Disable zoom with `<Frame zoom={false}>`.

## Heading anchor links

Every `h2` and `h3` heading is a permalink. Selecting the heading copies the
section URL without adding a visible marker beside it, so you can share a
specific answer while keeping the page visually clean.

## Typographic quotes

Straight quotes in prose render as written. Set `smartQuotes` at the top level
of `docs.json` to show them as curly quotes, the way Mintlify does:

```json
{
  "smartQuotes": true
}
```

With it on, `"quoted"` shows as “quoted” and `doesn't` as doesn’t. Only
rendered prose changes. Inline code, code blocks, math, link addresses, JSX
attributes (such as a `title`), heading anchors, the Markdown copy, `llms.txt`
and search results keep the straight quotes you wrote. Dashes and ellipses are
not changed. Migrated Mintlify sites turn it on.

## Tables

Standard Markdown tables render with proper styling:

```mdx
| Method | Endpoint | Description |
| --- | --- | --- |
| GET | /pets | List all pets |
| POST | /pets | Create a pet |
```

## Reusable snippets

Repeated content — an install note, a support callout, a compatibility warning — lives once in the `snippets/` folder and is imported into any page. Editing the snippet updates every page that uses it.

Import it at the top of your MDX file (the name you choose is up to you), then render it as a component wherever you need it:

```mdx
import { GettingStartedTip } from '/snippets/getting-started-tip.mdx'

<GettingStartedTip />
```

Rendered from `snippets/getting-started-tip.mdx`, this page shows:

<GettingStartedTip />

## File organization

All content lives in `src/content/`. You can use subdirectories to organize related pages:

```text title="File tree"
src/content/
  introduction.mdx          → /introduction (or / for the root)
  quickstart.mdx             → /quickstart
  guides/
    writing-content.mdx      → /guides/writing-content
    branding-and-theming.mdx → /guides/branding-and-theming
```

The URL path matches the file path relative to `src/content/`, minus the `.mdx` extension.
