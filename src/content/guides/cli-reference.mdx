The generated project includes `@thallylabs/cli`, so you can run the unified
CLI with `npx thally` from the project root. The command keeps routine work
focused on content and configuration instead of Next.js internals.

```bash
npx thally
```

## Commands

| Command | What it does |
| --- | --- |
| `thally init [dir]` | Create a project with `create-thally-docs`. |
| `thally dev [-- OPTIONS]` | Start the local documentation server and print its agent endpoints. |
| `thally build` | Build the production site. |
| `thally start` | Serve a completed production build. |
| `thally deploy [--prod] [--cloudflare]` | Build and deploy with Vercel or Cloudflare Workers. |
| `thally check [dir] [--agents] [--fix] [--ci] [--external] [--drift]` | Validate content and optional agent-readiness checks. |
| `thally new PAGE_ID` | Create an MDX page and register it in `docs.json`. |
| `thally migrate SOURCE [dir] [--platform mintlify\|docusaurus\|fern\|auto]` | Import a documentation repository or public site. |
| `thally translate --locale LOCALE` | Generate or refresh a translated content tree. |
| `thally mcp` | Start the local MCP server over standard input/output. |
| `thally agent "INSTRUCTION"` | Draft a documentation change for review. |
| `thally track add`, `list`, `test`, or `setup` | Connect product-repository changes to documentation work. |

Run `npx thally --help` to see the current command list, and
`npx thally COMMAND --help` for a command's options. Help never runs the
command, and unknown options are rejected with a pointer to that help.

### Preview and build

```bash
npx thally dev
npx thally build
npx thally start
```

`dev` starts the project server. Once it is ready, it prints the local
`llms.txt`, `/api/mcp`, and Agent Readiness URLs plus a
`claude mcp add --transport http` command for connecting Claude Code to the
preview. `build` creates the production output, and `start` serves an existing
production build. Options for the underlying server go after `--`, for example
`npx thally dev -- --port 4000`. These commands stop with an `npm install`
reminder when the project's dependencies are missing.

### Add and check content

```bash
npx thally new guides/invite-a-member \
  --title "Invite a team member" \
  --description "Add a teammate and choose their role."

npx thally check
```

`new` creates the MDX file and registers it in the last group of the first
content tab. `check` validates the project. Add `--ci` for GitHub annotations,
`--external` to check external links, `--drift` to evaluate provenance, or
`--agents` to include the Agent Readiness Score. `--external` sends bounded
`HEAD` requests (eight at a time, eight-second timeout, at most 300 unique
URLs) only to hosts that resolve to public addresses, and reports broken links
as warnings that never fail the check.

### Deploy

```bash
npx thally deploy --prod          # Vercel
npx thally deploy --cloudflare    # Cloudflare Workers
```

The deploy command builds the provider-specific artifact and runs the Agent
Readiness Score before it publishes. It then prints the deployed URL reported by
Vercel or Wrangler (falling back to `THALLY_SITE_URL`) with its agent endpoints,
and reports the readiness result; a low score is shown but does not stop the
deploy. See [Deploying](/guides/deploying) for host configuration and durable
storage.

## Scaffold with create-thally-docs

Use `create-thally-docs` directly when you are creating or migrating a project:

```bash
npx create-thally-docs@latest [command] [args] [options]
```

---

### Create a project

Creates a new Thally documentation project.

```bash
npx create-thally-docs my-docs
```

The CLI walks through an interactive setup:

- **Project directory** and **project name** — displayed in the header and metadata
- **GitHub repo URL** — optional; auto-wires Support and GitHub links
- **Thally Track** — optional; keep docs in sync with product pull requests
- **Install dependencies now** — yes by default, so the preview command works right away
- **Additional languages** — optional

The description and brand palette default sensibly and are one-line edits in
`src/data/site.ts`.

Skip all prompts and accept defaults with `--yes`:

```bash
npx create-thally-docs my-docs --yes
```

### Options

| Flag | Description |
|------|-------------|
| `--yes`, `-y` | Accept all defaults, skip interactive prompts |
| `--install` | Install project dependencies (the default) |
| `--no-install` | Skip dependency installation |

## Migrate existing documentation

Migrates a GitHub documentation repository or any public documentation URL into a Thally project.

```bash
npx create-thally-docs migrate <github-or-docs-url> [output-dir] [options]
```

For repositories, Thally reads Markdown, MDX, navigation, local snippets, assets, locales, redirects, and OpenAPI files. For live Mintlify sites, it first recovers the structured configuration embedded in the rendered application, then fetches page content from Markdown endpoints. Other live sites use `llms.txt`, path-scoped sitemaps, and navigation links before falling back to HTML conversion.

**Supported source platforms:** Mintlify, Docusaurus, Fern, GitBook, Nextra, VitePress, Starlight, and any repo with plain Markdown files.

Interactive runs ask which platform currently hosts the docs. Selecting Mintlify keeps the existing Mintlify projection; selecting Docusaurus uses its sidebar, route, syntax, and asset adapter; selecting Fern uses the Fern adapter. Choose automatic detection for another platform.

When automatic detection receives a live website URL, the CLI first recommends migrating its source GitHub repository. Repository migrations retain authored navigation, assets, OpenAPI files, and component structure that may not be recoverable from rendered HTML. If you continue with the live URL, you must accept that the result may need manual alignment; use the Thally MCP afterward to refine the generated project when needed.

Scripts can make the same platform choice with `--platform`. Explicit `--platform auto` and `--yes` runs print the live-site warning but remain non-interactive.

### Examples

```bash
# Migrate into a new project at ./my-docs
npx create-thally-docs migrate https://github.com/org/repo my-docs

# Derive the output dir from the repo name
npx create-thally-docs migrate https://github.com/mintlify/starter

# Select the Docusaurus adapter explicitly in a script
npx create-thally-docs migrate https://github.com/facebook/docusaurus website-docs --platform docusaurus

# Select the Fern adapter explicitly in a script
npx create-thally-docs migrate https://github.com/fern-api/docs-starter --platform fern

# Migrate a live docs site without its source repository
npx create-thally-docs migrate https://docs.example.com my-docs

# Keep a large public crawl bounded
npx create-thally-docs migrate https://example.com/docs my-docs --max-pages 200

# Migrate a specific branch or subdirectory
npx create-thally-docs migrate https://github.com/org/repo/tree/main/docs my-docs

# Migrate content into an existing Thally project
npx create-thally-docs migrate https://github.com/org/repo --into ./existing-docs
```

### What gets migrated

- All documentation `.md` and `.mdx` files are copied; repository-only files such as `README.md` and `AGENTS.md` are excluded
- Current Mintlify `docs.json` navigation, local `$ref` files, languages, nested groups, tabs, anchors, products, dropdowns, versions, hidden state, and global navigation are projected without flattening the source information architecture
- Mintlify route casing, directory landing redirects, page metadata, reusable snippets with static props, compatible site settings, configured OpenAPI files, and local assets are preserved
- Docusaurus `sidebars.js/ts/json`, category shorthand, autogenerated slices, `id`, `slug`, `sidebar_position`, generated indexes, numeric prefixes, admonitions, tabs, and root `static/` assets are projected through a dedicated adapter
- Docusaurus sidebar modules are parsed statically as bounded data-only objects; source JavaScript and TypeScript are never executed, and executable configs fall back to generated navigation with a warning
- Fern `fern/docs.yml` tabs, nested sections (including `slug`/`skip-slug`), navbar links, redirects, and the default version's navigation are projected through a dedicated adapter; only pages referenced from `docs.yml` are imported
- Imported MDX snippets are inlined, while components already supported by Thally are preserved
- Public URL crawls remain on the submitted origin and docs path, preventing an origin-wide sitemap from importing marketing or blog pages
- OpenAPI spec files (`.json`, `.yaml`) are detected and wired up as an API Reference tab
- Static repository assets are copied into `public/`

### Options

| Flag | Description |
|------|-------------|
| `--into <dir>` | Migrate into an existing Thally project instead of scaffolding a new one |
| `--branch <name>` | Override the auto-detected git branch |
| `--docs-dir <path>` | Override the auto-detected docs subdirectory |
| `--max-pages <count>` | Maximum pages for a public URL crawl (default and maximum `1000`) |
| `--platform <name>` | Select `mintlify`, `docusaurus`, `fern`, or `auto` instead of answering interactively |
| `--yes`, `-y` | Skip prompts; platform auto-detection is used unless `--platform` is set, and live-site limitations are accepted non-interactively |

### Component mapping

Thally renders Mintlify's common MDX components directly. The importer only renames syntax that does not have the same component name:

| Source | Thally equivalent |
|--------|---------------|
| `<Check>` | `<Note>` |
| `<Danger>` | `<Error>` |
| `<Warn>` | `<Warning>` |
| `<Tree.Folder>` | `<Folder>` |
| `<Tree.File>` | `<File>` |
| `<AccordionGroup>` | stripped (children kept) |
| `<Expandable title="...">` | `<Accordion title="...">` |
| `<ResponseField>` / `<ParamField>` | Markdown property definition |
| `<RequestExample>` / `<ResponseExample>` | `<CodeGroup>` |
| `<Tile>` | `<Card>` |
| Docusaurus `:::note` / `:::tip` | `<Note>` |
| Docusaurus `:::warning` / `:::caution` | `<Warning>` |
| Docusaurus `:::danger` | `<Error>` |
| Docusaurus `<TabItem>` | `<Tab>` |

<Note title="Non-Markdown files">
Files in `.rst` or other formats require an Anthropic API key to convert. Set `ANTHROPIC_API_KEY` in your environment or pass `--api-key`. Plain `.md` and `.mdx` files are migrated for free.
</Note>

## Check a project

Lints a Thally project for common issues and reports errors and warnings.

```bash
npx create-thally-docs check [project-dir]
```

Defaults to the current directory if no path is given.

### What it checks

| Issue | Severity |
|-------|----------|
| Page listed in `docs.json` but no MDX file found | Error |
| Page reused in more than one `docs.json` section | Warning |
| Tab with no groups and no `href` | Error |
| MDX syntax error in a page or in a `snippets/` file, such as a JSX attribute with escaped quotes (it cannot be parsed, so it cannot render) | Error |
| MDX file not listed in `docs.json` (orphan) | Warning |
| Missing `title` in frontmatter | Warning |
| Missing `description` in frontmatter | Warning |
| Empty or near-empty page body | Warning |
| Redirect from a link-only page that ends at a missing page or loops | Error |

A page that only stands in for a link elsewhere (a `noindex` page whose own address redirects to another site or to a path on this one, which a migrated Mintlify `url` entry becomes) is not checked for a `description` or a body, because no visitor reads it. That holds only while the redirect leads somewhere: if it ends at a page that does not exist, or comes back to itself, the check reports the broken redirect and keeps the notices about the page.

```bash
# Check the current project
npx create-thally-docs check

# Check a specific directory
npx create-thally-docs check /path/to/my-docs

# Auto-fix orphan files by adding them to the nav
npx create-thally-docs check --fix
```

The CLI exits with code `1` if any errors are found, `0` if the project is clean or only has warnings.

The MDX check reads each file with the parser the site renders with, so it catches syntax errors only. A page that parses can still fail to compile, for example when it declares two default exports.

### Options

| Flag | Description |
|------|-------------|
| `--fix` | Auto-add orphan pages to the last group of the first content tab |
| `--ci` | Print GitHub annotations and a compact summary |
| `--drift` | Flag pages whose `sources` changed since `verifiedCommit` |
| `--external` | Also check external links on public hosts (bounded; warnings only) |

## Translate content

Translates documentation pages to a secondary locale using Claude AI. Requires an `i18n` block in `docs.json`.

```bash
npx create-thally-docs translate --locale es
```

Translated files are written to `src/content/{locale}/` for you to review and commit — no runtime cost, full SSG.

### Examples

```bash
# Translate all pages to Spanish
npx create-thally-docs translate --locale es

# Translate specific pages only
npx create-thally-docs translate --locale fr --pages introduction,guides/getting-started

# Overwrite existing translations
npx create-thally-docs translate --locale es --force

# Pass API key explicitly
npx create-thally-docs translate --locale de --api-key sk-ant-...
```

### Options

| Flag | Description |
|------|-------------|
| `--locale <code>` | Target locale code — required (must be in `docs.json` i18n config) |
| `--pages <ids>` | Comma-separated page IDs to translate (omit for all pages) |
| `--force` | Overwrite existing translation files |
| `--api-key <key>` | Anthropic API key (falls back to `ANTHROPIC_API_KEY` env var) |
| `--model <id>` | Claude model to use (default: `claude-sonnet-4-6`) |
| `--yes`, `-y` | Skip confirmation prompt |

See [Multi-Language Support](/guides/multi-language) for full setup instructions.
