## The docs.json file

All navigation is controlled by a single file at the project root: `docs.json`. It defines the collections readers can switch between, the sidebar groups within each collection, and the order of pages.

## Structure

```json
{
  "tabs": [
    {
      "tab": "Tab Label",
      "groups": [
        {
          "group": "Section Title",
          "pages": ["page-one", "page-two"]
        }
      ]
    }
  ]
}
```

## Collections

Each entry in the `tabs` array creates a top-level documentation collection. On desktop, collection tabs always appear in their own row below the logo, language selector, and search. Labels keep their full text without horizontal scrolling or truncation. When space is limited, items wrap onto additional lines; an unusually long label can wrap within its item. Mobile navigation stays in its drawer.

This behavior comes with the shared runtime: new sites inherit it from their selected starter release, and existing sites receive it when their runtime is updated and the site is rebuilt. No site-specific configuration is needed. Set `navigation.display` to `"dropdown"` to present collections in a sidebar selector instead:

```json
{
  "navigation": { "display": "dropdown" },
  "tabs": [
    {
      "tab": "Documentation",
      "description": "Guides and concepts",
      "icon": "book-open",
      "groups": []
    },
    {
      "tab": "API",
      "description": "Endpoints and schemas",
      "icon": "code",
      "groups": []
    }
  ]
}
```

The optional `description` and `icon` fields appear in the collection selector. There are three collection types:

### Content tab

A tab with sidebar groups and pages:

```json
{
  "tab": "Overview",
  "groups": [
    { "group": "Getting Started", "pages": ["introduction", "quickstart"] },
    { "group": "Core Concepts", "pages": ["guides/writing-content"] }
  ]
}
```

### API Reference tab

A tab that auto-generates pages from an OpenAPI spec:

```json
{
  "tab": "API Reference",
  "api": {
    "source": "openapi.yaml",
    "tagsOrder": ["Posts", "Comments"],
    "defaultGroup": "General"
  }
}
```

### Link tab

A tab that links to an internal route or external URL:

```json
{
  "tab": "Changelog",
  "href": "/changelog"
}
```

## Groups

Groups create labeled sections in the sidebar. Each group has:

- **`group`** — the section heading displayed in the sidebar
- **`pages`** — an ordered array of page IDs

`pages` may also contain nested group objects. Thally preserves their authored position and renders them as collapsible branches:

```json
{
  "group": "Writing tasks",
  "pages": [
    "writing-tasks/overview",
    {
      "group": "Wait",
      "pages": ["wait/overview", "wait/for", "wait/until"]
    },
    "writing-tasks/idempotency"
  ]
}
```

For a collection with ungrouped root pages, put `pages` directly on the tab.
This keeps root pages and nested groups in one exact authored sequence without
adding a synthetic section heading.

Page IDs map to file paths under `src/content/`. For example:

| Page ID | File path |
| --- | --- |
| `"introduction"` | `src/content/introduction.mdx` |
| `"guides/writing-content"` | `src/content/guides/writing-content.mdx` |
| `"api/overview"` | `src/content/api/overview.mdx` |

## Adding a new section

To add a new sidebar section, add a group object to the relevant tab:

```json
{
  "tab": "Overview",
  "groups": [
    { "group": "Getting Started", "pages": ["introduction", "quickstart"] },
    { "group": "Advanced", "pages": ["guides/deploying", "guides/seo-and-visibility"] },
    { "group": "New Section", "pages": ["my-new-page"] }
  ]
}
```

## Reordering

Pages and nested groups appear in the sidebar in the exact order listed in the `pages` array. Top-level groups appear in the order they're defined in the `groups` array. Collections appear in the order defined in the `tabs` array.

## Group icons

Add an `icon` field to any group to display an icon next to the group heading in the sidebar:

```json
{
  "group": "Getting Started",
  "icon": "book-open",
  "pages": ["introduction", "quickstart"]
}
```

Available icon names:

| Name | Icon |
| --- | --- |
| `book-open` | Book / documentation |
| `code-simple` | Code brackets |
| `grid-round` | Grid / overview |
| `link-simple` | Link / URL |
| `wrench` | Tools / settings |
| `party-horn` | Features / celebration |
| `telegram` | Send / messaging |
| `envelope` | Email |
| `x-twitter` | X / Twitter |
| `message` | Chat / message |

## Page eyebrow

The small line above a page title shows where the page sits in the sidebar. By default it is the name of the page's nearest group. Set `eyebrow` at the top level of `docs.json` to show the whole group path instead:

```json
{
  "eyebrow": "path",
  "tabs": [...]
}
```

| Value | Result for a page in `Errors`, then `Frontline errors`, then `Capacity` |
| --- | --- |
| `"group"` (default) | `Capacity` |
| `"path"` | `Errors › Frontline errors › Capacity` |

The path leaves out the tab and the page title, and its items are plain text, not links. A page outside any group has no eyebrow. Generated endpoint pages have none either. `eyebrow` is independent of `breadcrumbs`, the trail of tab, groups and page title: `"breadcrumbs": false` hides only the trail.

## Hiding groups and tabs

Set `hidden: true` on a group or tab to exclude it from the sidebar while keeping its pages accessible by URL:

```json
{
  "group": "Internal",
  "hidden": true,
  "pages": ["internal/roadmap", "internal/notes"]
}
```

```json
{
  "tab": "Staff Only",
  "hidden": true,
  "groups": [...]
}
```

Hidden pages remain reachable by direct URL, but they do not appear in
navigation or sitemaps. See [Control search and page visibility](/guides/seo-and-visibility)
for more indexing controls.

## Hiding a version

In `navigation.versions`, set `hidden: true` on an entry to remove it from the version switcher while keeping its pages reachable by URL. The switcher stays visible as long as one visible entry is left:

```json
{ "label": "v1", "prefix": "v1", "href": "/v1/introduction", "hidden": true }
```
