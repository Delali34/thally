---
title: "ParamField"
description: "Document request parameters — body, query, path, and header."
---

`<ParamField>` renders a structured parameter entry for API request documentation. Put the parameter name directly in the `body`, `query`, `path`, or `header` prop. The older boolean location plus `name` form remains supported.

## Example

<ParamField body="name" type="string" required>
  The name of the pet. Must be between 1 and 100 characters.
</ParamField>

<ParamField query="limit" type="integer" default="20" placeholder="25">
  Number of results to return. Maximum is 100.
</ParamField>

<ParamField path="petId" type="string" required>
  The unique identifier of the pet.
</ParamField>

<ParamField header="Authorization" type="string" required>
  Bearer token for authentication: `Bearer sk-...`
</ParamField>

```mdx
<ParamField body="name" type="string" required>
  The name of the pet.
</ParamField>

<ParamField query="limit" type="integer" default="20">
  Maximum results to return.
</ParamField>

<ParamField path="petId" type="string" required>
  The unique identifier.
</ParamField>
```

## Props

| Prop | Type | Description |
|---|---|---|
| `type` | `string` | Data type (e.g. `string`, `integer`, `boolean`) |
| `body` | `string` | Request body parameter name |
| `query` | `string` | Query string parameter name |
| `path` | `string` | Path parameter name |
| `header` | `string` | Request header name |
| `required` | `boolean` | Shows a "required" badge |
| `deprecated` | `boolean` | Marks the parameter as deprecated |
| `default` | `any` | Default value shown inline |
| `placeholder` | `string` | Suggested input shown by API tooling |

## Linking to a field

Every `<ParamField>` and `<ResponseField>` gets an anchor made from its name: `param-` followed by the name in kebab case, so `expiresInDays` is `#param-expires-in-days`. A name used twice on one page is numbered from `-1` (`#param-key-id`, `#param-key-id-1`), and a link to a field inside a collapsed `<Expandable>` opens it.
